# CHZZK All-in-One by hanbi

Firefox 우선으로 만든 비공식 CHZZK 통합 확장 프로그램입니다.

공통 소스 버전은 **1.1.27**이며, 같은 기능 소스로 Firefox와 Chrome 빌드를 만듭니다. 1.1.25는 서버가 480p 이하만 주는 제한 중계를 Q 버튼에 `제한`으로 표시하고(화질을 높이지는 않음), 새로 들어온 채팅만 아래에서 짧게 밀려 올라오게 합니다(1.1.27, 기존 채팅은 움직이지 않아 읽기 편함. 설정에서 끌 수 있음). 1.1.24는 컴프레서 컨트롤이 플레이어 UI와 함께 숨겨지게 하고, RAW 녹화가 버퍼링·광고 영상에 끊기지 않게 하며, 전체화면에서도 녹화 표시와 안내가 보이게 고쳤습니다(실방송 확인 전). 1.1.23은 Chrome `PIP` 버튼을 복구하고, PIP·광고·버퍼링·사이트 내 이동 중에도 REC가 끊기지 않게 고쳤으며, 통나무 시청 보상 로그를 실제 잔액 증가로만 기록합니다. Chromium 테스트 페이지에서 PIP 녹화 유지, 컴프레서 출력 변화, 음소거 녹화의 원본 소리를 측정했고(실방송 아님), Chrome의 PIP·녹화는 사용자가 실제로 써 보고 동작을 확인했습니다. Firefox 1.1.23 실환경과 통나무 실제 지급 로그는 아직 확인 전입니다. 이전 Chrome 녹화·MP4 검증 범위는 [HANDOFF.md](HANDOFF.md)에 기록하며, 모든 기능의 실방송 검증이 끝난 상태는 아닙니다.

## 주요 기능

- GRID/P2P 우회, 1080p 최고 화질 선택 (서버에 1080p가 없으면 최고 가용 화질)
- 식별 가능한 광고 미디어 건너뛰기 및 광고 차단 경고 팝업 숨김 (실방송 검증 필요)
- 녹화 중 청취, 녹화 결과 미리보기, WebM/MP4 원본 및 MP4/GIF/WebP 변환·자르기·분할, 별도 RAW 조각 저장
- 스크린샷 미리보기·저장, Chrome `PIP` 버튼 (PIP 중에도 녹화 유지. Firefox는 자체 PiP 버튼이 있어 확장 버튼을 만들지 않음)
- 통나무 파워 자동 획득·보유량·로그·승부예측 기록 (시청 보상 로그는 실제 잔액 증가가 확인될 때만 기록)
- 확인 가능한 블라인드 채팅 원문 표시
- 실시간 트렌드 썸네일과 팔로잉 방송 hover 영상 미리보기 (무음, 로딩·실패 시 썸네일)
- 로그인 계정의 팔로잉 방송 시작만 표시하는 페이지 내 팝업
- cheese-knife 방식의 HLS 버퍼 보존·강제 라이브 복귀 방지·`buffered` 탐색 (현재 Firefox 실방송 검증 필요)
- 오디오 컴프레서, 밝기·대비·선명도, 채팅·사이드바 보조 기능

REC 원본은 CHZZK 전송 파일의 무손실 복사본이 아니라 MediaRecorder가 재인코딩한 결과입니다. 1.1.20부터 H.264/AAC MP4 녹화가 가능한 브라우저에서는 MP4로 기록하고, 지원하지 않거나 시작에 실패하면 기존 WebM으로 돌아갑니다. 확인된 AVC/AAC MP4의 MP4 버튼은 원본을 재인코딩 없이 저장합니다. 기존 WebM의 MP4 변환·MP4 자르기·분할은 원본 타임스탬프를 유지해 1000fps 프레임 복제를 막지만 여전히 인코딩 시간이 필요합니다. 1.1.11부터 영상 해상도에 따라 목표 비트레이트를 높여 기존 기본값의 뭉개짐을 줄입니다. 녹화 파일 크기와 CPU 사용량이 늘 수 있으며, 방송 원본과 바이트 단위로 같은 품질은 보장하지 않습니다.

1.1.12의 라이브 플레이어 `RAW`는 별도 저장 방식입니다. 본방송 HLS 플레이어가 새로 받는 압축 조각을 복사해, TS 방송은 `.ts`, 분할 MP4 방송은 초기화 조각을 포함한 `.mp4`로 직접 다운로드합니다. 다시 인코딩하지 않으므로 수신한 화질·코덱을 유지하지만, CHZZK가 제공하지 않는 고화질을 만들어 내지는 않습니다. 기존 `REC`와 결과 창·변환기는 그대로 사용할 수 있습니다. RAW는 기존 버퍼의 과거 구간을 소급 저장하지 않으며, 오디오가 별도 트랙이거나 암호화·저지연 부분 조각·화질 전환·조각 누락이 감지되면 중단하고 받은 구간의 부분 파일 다운로드를 요청합니다. 장시간 녹화는 탭 메모리를 많이 사용합니다. **Firefox와 실제 CHZZK 방송에서 RAW 파일의 오디오·재생·다운로드는 아직 검증 전입니다.**

## Chrome 테스트 설치

1. `.\build.ps1 -Browser Chrome`을 실행하면 `dist/chzzk-all-in-one-chrome-v<버전>/`와 같은 이름의 ZIP이 생성됩니다. 이미 만들어 둔 `dist/chzzk-all-in-one-chrome-v1.1.27/`을 바로 써도 됩니다.
2. Chrome의 `chrome://extensions`에서 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램을 로드합니다**를 눌러 위 폴더를 선택합니다. ZIP 파일을 직접 선택하지 않습니다.
4. CHZZK 탭을 새로고침합니다. SHOT의 탭 캡처를 테스트할 때는 해당 방송 탭에서 확장 아이콘을 눌러 설정 팝업을 한 번 엽니다.

Chrome 빌드는 서비스 워커·선언형 GRID 요청 규칙·JSON 메시지로 나눈 녹화 전송을 사용합니다. GRID의 고화질 요청이 실패하면 약 60초 동안 원본 요청을 허용해 플레이어의 다음 재시도가 저화질로 진행하게 합니다. 실패한 현재 응답을 바로 원본으로 리다이렉트하는 Firefox와 달리 첫 실패 때 잠깐 지연될 수 있습니다. Chromium 요청 엔진에 테스트 응답을 제공한 403→원본 재시도는 확인했으며 실제 방송의 1080p 및 실패 후 재생 회복은 추가 확인이 필요합니다. Chrome의 녹화·설정·로그 저장소는 Firefox의 기존 데이터와 별개입니다.

Chrome 120 이상을 빌드 대상으로 지정했으며, 자동 실환경 검증은 기존에 설치돼 있던 Chromium 148 임시 프로필에서 실행했습니다. 사용자 Chrome 144 프로필과 Firefox 설치를 변경하지 않았고 새 브라우저나 보조 프로그램을 설치하지 않았습니다.

## Firefox 설치

`build.ps1`이 만드는 `.xpi`는 ZIP의 복사본인 **미서명 개발용 파일**입니다. 일반 Firefox의 영구 설치에는 Mozilla 서명본이 필요합니다. 서명 전에는 `about:debugging#/runtime/this-firefox`의 **임시 부가 기능 로드**에서 `manifest.json`을 선택해 테스트할 수 있습니다.

### 가장 쉬운 서명 방법: 웹에서 직접 업로드

1. 평소 쓰는 브라우저에서 [AMO 개발자 허브](https://addons.mozilla.org/developers/)에 Mozilla 계정을 만들고 로그인합니다. 일반 Firefox용 서명에는 계정이 필요합니다. Codex 브라우저에서 로그인할 필요는 없습니다.
2. 이미 1.1.10을 승인받았다면 **기존 부가 기능 관리 페이지의 새 버전 업로드**를 선택합니다. 처음 제출하는 경우에만 **새 부가 기능 제출** → **On your own(직접 배포)**을 선택합니다.
3. 실제 방송에서 확인한 버전의 `dist/chzzk-all-in-one-firefox-v<버전>.zip`을 업로드하고 화면의 검증·심사 절차를 마칩니다. 이후 소스를 수정했다면 `.\build.ps1 -ZipOnly`로 새 ZIP을 만듭니다.
4. [AMO 버전 페이지에서 Mozilla가 서명한 XPI를 내려받습니다](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/). 제출 즉시 발급되지 않을 수 있으며, 검증 오류가 있으면 AMO의 오류 내용을 확인해야 합니다.

반복 서명이 필요할 때만 API 키를 발급해 `WEB_EXT_API_KEY`, `WEB_EXT_API_SECRET` 환경 변수를 설정하고 `.\sign.ps1`을 실행할 수 있습니다. 이 스크립트는 패키지를 Mozilla에 제출하고 서명본을 `dist/signed-v<버전>/`에 받습니다. 키는 저장소나 패키지에 넣지 않습니다. 스크립트 실행에는 Node.js 22 이상과 npm이 필요하지만 Firefox 사용 시 별도 프로그램은 필요 없습니다.

서명된 `.xpi`를 Firefox의 `about:addons` → 톱니바퀴 → **파일에서 부가 기능 설치**로 설치합니다. 기존 임시 부가 기능이 켜져 있으면 먼저 제거하고, 설치 후 CHZZK 탭을 새로고침해 이전 페이지 후킹을 없앱니다.

## 1.1.23 PIP·녹화 유지·통나무 로그

- Chrome 플레이어에 `PIP` 버튼이 다시 생깁니다. 녹화 중에 누르면 녹화 중인 영상이 PIP 창으로 뜹니다. Firefox는 자체 PiP 버튼을 쓰므로 확장 버튼이 없습니다.
- REC는 녹화 중인 영상이 페이지에서 사라지거나 다른 방송으로 이동할 때만 끝납니다. 이전에는 광고처럼 더 큰 영상이 나타나거나 버퍼링으로 잠깐 멈추기만 해도 끊겼습니다. PIP로 보는 중이면 사이트 안에서 다른 페이지로 가도 녹화가 이어집니다.
- 통나무 1시간 시청 보상은 버튼을 누른 뒤 실제 잔액이 늘어난 것이 확인될 때만, 그 증가분으로 기록합니다. 저장에 실패하면 다음 조회 때 다시 기록하고, 여러 탭이 같은 증가를 중복 기록하지 않습니다.

## 1.0.7 화질/GRID 회귀 수정

1.0.5~1.0.6에서 최고 화질 선택을 단순 순서 변경으로 약화한 것을 되돌렸습니다. 480p→1080p 우회는 별도 확장 fetch가 아니라 실제 플레이어 요청을 리다이렉트합니다. 실제 403/404 응답이면 원래 화질 요청으로 복귀하며, 실패한 경로는 60초 동안 재우회하지 않습니다. 네트워크 오류는 다음 재시도부터 원본 경로를 사용합니다.

blob/worker 요청의 문서 출처 판정, 중첩·객체형 재생 JSON 및 축약 P2P 필드 처리를 보완했습니다. 타임머신·녹화·오디오 코드는 이 버전에서 변경하지 않았습니다. 자동 회귀 테스트 통과와 실제 Firefox 방송의 화질 메뉴/GRID 안내 검증은 별개입니다.

## 1.0.6 타임머신 로직 복원

cheese-knife의 `setSeeking`/`patchHls` 구조에 맞춰 MAIN world에서 실제 HLS 컨트롤러를 찾고, 과거 버퍼 보존과 강제 라이브 복귀 억제를 함께 적용합니다. TM 패널·방향키 모두 동일한 `buffered` 탐색 경로를 사용합니다. LIVE·패널 닫기·채널/플레이어 교체 시 원래 설정과 동기화 함수를 복원합니다.

1.1.13부터 TM 패널이 활성화된 동안 HLS의 과거 버퍼 자동 제거 제한을 `Infinity`로 설정합니다. 기존의 전방 버퍼 설정, 탐색, LIVE 복귀 및 원래 설정 복원은 유지합니다. Firefox가 메모리 압박으로 버퍼를 직접 제거할 수 있으므로 실제 보존 길이는 무제한으로 보장되지 않습니다. 이미 버려진 과거 영상을 되살리는 서버 DVR 기능도 아닙니다. **로직 회귀 테스트와 별개로 로그인된 Firefox에서 실제 작동 확인은 아직 필요합니다.**

1.1.16은 일시정지 버퍼 유지 기능에서 사이트의 streaming profile이 앞쪽 버퍼 상한을 15초로 덮던 문제를 수정합니다. 이미 재생 중이던 본방송을 일시정지하면 TM 패널 없이도 재생 위치를 멈춘 채 앞쪽 버퍼 목표를 1시간으로 높이고 중단된 HLS 조각 로딩을 재개합니다. 재생 이벤트에서 사이트가 자동으로 라이브 끝으로 보내는 이동을 제한해, 버퍼가 남아 있으면 멈춘 위치에서 이어 봅니다. 재생을 다시 시작하면 앞쪽 버퍼 목표를 되돌리고, LIVE·닫기·플레이어 교체 시 사이트 설정과 연결한 함수를 복원합니다. 실제 보존 길이는 Firefox의 메모리·MSE 한도에 좌우되며, hls.js가 메모리 오류를 회복하려고 목표를 낮출 수 있습니다. REC는 시청 음소거와 독립적인 캡처 스트림을 녹화하고 시청용 모니터만 음소거합니다. 실제 Firefox 녹화 파일의 소리는 수동 확인이 필요합니다.

## 1.0.5 수정 범위와 미확인 사항

- 일반 MP4/`service` 경로를 광고로 오인해 `src`를 지우던 처리와 추측한 타임머신 API 호출·XHR 지연을 제거했습니다.
- 480p→1080p 우회는 후보 재생 목록 및 첫 미디어 세그먼트 접근을 확인한 뒤에만 수행합니다. 목록 요청이 403/404로 바뀌면 원래 요청으로 복귀합니다. Firefox `webRequest`/`webRequestBlocking` 권한을 사용하며 기존 무조건 치환 규칙은 비활성화합니다.
- 팔로잉 알림은 전체 팔로잉 API 목록, 계정별 기준 상태, 탭 간 조회 잠금과 5초 최소 간격을 사용합니다. 처음 관찰한 라이브·계정 전환·오류·오래된 상태는 시작 알림으로 처리하지 않습니다.
- 컴프레서 그래프를 영상별로 재사용하고 동일 모드 재연결을 생략합니다. 연결 실패 시 원음 경로로 복귀합니다.
- 구매 안내는 해당 모달 배경까지 숨기며 가능한 경우 사이트의 닫기 핸들러를 먼저 호출합니다. 다른 모달은 건드리지 않습니다.

**타임머신 완전 복구 및 핵심 4종 실방송 합격을 의미하지 않습니다.** TM 패널은 현재 영상이 제공하는 범위만 탐색합니다. 과거 데이터가 없으면 서버 타임머신을 만들어 내지 못합니다. 문제 방송에서 `TM → 재생 진단 정보`를 펼치면 토큰·쿠키·영상 URL을 제외한 영상 상태와 탐색 범위를 복사할 수 있습니다. 로그인된 Firefox에서 재현 검증은 아직 필요합니다.
